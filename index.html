How to run it

One post = one fresh chat. Never mix two posts in one chat. The prompts are JSON specifications — paste them whole, braces included.

1 · Generate the raw space
Set your options, pick the image size in the toolbar, copy Prompt 1 and paste it into a new chat. Check the result: space genuinely empty, camera level, correct aspect ratio, no text. Save it as 01-before.png. If the model replies by describing the JSON instead of generating, send: Generate the image now.
2 · Add the design layer
Attach 01-before.png to your next message, then paste Prompt 2. The geometry_lock block is what keeps the walls, windows and camera identical — do not delete it. Verify nothing architectural moved, then save as 02-after.png.
3 · Build the cover
Attach both images, paste Prompt 3. The template carries exact pixel coordinates for the chosen size, so every post in your feed lines up. For reels the split is horizontal — before on top, after below — and the top 250 px and bottom 420 px are kept clear of Instagram's own UI. Check the headline spelling, this is the most common failure. Save as 00-cover.png.
4 · Get the caption and hashtags
Paste Prompt 4 in the same chat so it can read the real design. On reel size you also get a 15–20 second voiceover script with timestamped on-screen text beats.
Full Tour mode · Walk a whole property (No before image needed!)
In Full Tour mode, you generate pure text-to-image from scratch — you do NOT need any existing or before image!

1. Prompt 1: Paste into a new chat. The AI invents the complete property design from text and generates Room 1. It prints a HOME_DNA block.
2. Prompts 2..n: Paste each prompt one after another in that SAME chat. The AI continues the locked design language into each new room without needing any image upload.
3. Thumbnail Collage: Paste in the same chat. The AI places all generated room images into a clean Instagram cover grid.
4. Caption & 5 Hashtags: Paste in the same chat for the final ready-to-post Instagram copy.
5 · Publish
Carousel order: 00-cover → 01-before → 02-after. For a reel, animate cover → before → after with a 1 second hold each and use the script as the voiceover. Paste the caption, publish, then add the first comment immediately.

Troubleshooting

Copy the fix line into the same chat — never restart from Prompt 1.

The model explains the JSON instead of generating
Do not describe the specification. Generate the image now, obeying every field as a hard requirement.
The "after" is a completely different space
That is a different space. Rebuild using the attached before image as a locked background plate — identical camera position, identical corners, identical openings. Add only the design layer.
Camera zoomed, tilted or re-framed
Restore the exact original framing, camera height and lens from the before image. Do not zoom or re-frame.
A window / door moved or appeared
Remove the added opening. Match the before image exactly — same count, same size, same position.
The space got bigger after designing
You enlarged the space. Keep the original dimensions and height. Reduce the number of elements instead.
Wrong aspect ratio
Regenerate at the exact pixel size in the output block of the specification. Do not crop or pad — compose for that frame.
Cover text is garbled or misspelled
Regenerate the cover. The headline must read exactly as given, rendered crisply with no extra or malformed characters.
Output looks like a plastic 3D render
Make it read as real architectural photography — natural light, realistic material imperfection, neutral white balance, visible contact shadows, no CGI sheen.
Too cluttered
Reduce the decor and planting by about 40%. Keep the layout and materials. Add more negative space and clear circulation.
Proportions are wrong
Fix human scale: seat 450 mm, dining table 750 mm, kitchen counter 900 mm, door 2100 mm, step riser 150 mm, switch plates 1200 mm, compound wall 1800 mm.
Every post looks different from the last
Attach your first approved cover and add: Match this template exactly. Only the two photos and the headline change.

Why these prompts work

The techniques baked into every generated prompt.

JSON specification

Fields are unambiguous. A model cannot skim past "aspect_ratio":"9:16" the way it skims past a clause buried in a paragraph, and nested blocks keep camera, materials and lighting from bleeding into each other.

Reference locking

Prompt 2 declares the previous image a locked background plate. This reframes the job from "generate a space" to "edit a layer" — the single biggest driver of before/after consistency.

Numbered invariants

The geometry lock is an enumerated list with an explicit allowed / forbidden split, not prose. Discrete numbered constraints are obeyed more reliably.

Self-written state notes

The AI records its own geometry and design decisions as text. Written notes survive across turns far better than visual memory alone.

Per-space element lists

Every one of the 85 spaces carries its own typical Indian dimension and a list of the elements it genuinely needs, so a clinic gets a hand-wash basin and a pooja room gets a jaali back panel without you typing either.

PBR material language

Roughness, specular response, grain direction and veining continuity are named the way a render engine names them, which is the vocabulary these models were trained on.

Millimetre ergonomics

Seat 450, counter 900, door 2100, switch plate 1200, walkway 900. Real numbers, not "comfortable proportions".

Indian construction reality

2100 mm door heights, 900 mm sills, chajja projections, 100 mm skirting, Kota and IPS floors, vastu orientation for pooja rooms — the details that separate a plausible Indian project from a Pinterest render.

Aspect-aware composition

The lens, the framing and the cover geometry all change with the selected size. Reels get a taller lens, a horizontal split and Instagram's UI safe areas.

Negative prompting

Explicit exclusion lists remove the usual artefacts. On Flux and SD the list is also copyable on its own for the tool's dedicated negative field.

Self-check before output

The prompt asks the model to verify its own work against the constraints before it renders, which catches drift that a plain instruction misses.

Graceful defaults

Every optional control resolves to an AI_DECIDES instruction telling the model to choose the best-matching value, so a minimal setup still produces a complete result.
